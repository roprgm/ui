## Examples

### Default

An Input is as tall as a Button of the same size, so the two sit in a row. Wrap it in a [Field](/components/field) to give it a label.

<Example name="input/demo" />

### Sizes

`default` and `lg`, as tall as a Button of each size.

<Example name="input/sizes" />

### Invalid

`aria-invalid` rings it red. A Field with an `error` sets it for you.

<Example name="input/invalid" />

### File

`type="file"` styles the picker's button as a control, 3px inside the field.

<Example name="input/file" />

### With addons

An `InputGroupAddon` puts an icon, a short text, or an icon button over the Input's `start` or `end`, centered in a column at least as wide as a default control. Text and icons let the pointer through to the field. The Input pads itself clear of it: `pl-7` for an icon, more for longer text.

<Example name="input/addons" />

An icon button at `icon-sm` takes the pointer, in a square as tall as the Input, so it sits as far from the edge as from the top and bottom.

<Example name="input/password" />

### With a copy button

A read-only link at `lg` holds a CopyButton at `icon-sm` in an addon, 4px from each edge.

<Example name="input/copy" />

## Anatomy

Each part's `data-slot`, which a theme styles, is beside it.

```tsx
<Input /> // input, with data-size
<InputGroup> // input-group
  <InputGroupAddon align="start" /> // input-group-addon, with data-align
  <Input /> // input
  <InputGroupAddon align="end" /> // input-group-addon, with data-align
</InputGroup>
```
